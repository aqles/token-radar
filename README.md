A dashboard ranking pre-token protocols by implied launch value, from a sealed DefiLlama snapshot — with a farm plan for every protocol. The radar-6 model prices each protocol as TVL × peer multiple × fitted size multiplier. The size multiplier comes from a log-log curve fit at run time (log(mcap) = 6.9646 + 0.5223·log(TVL), ordinary least squares on 128 traded comparables), clamped to [0.5×, 2×] of the category peer multiple — the clamp keeps giants credible (Sentora: 0.2138× peer → 0.0327× unbounded curve → 0.107× adopted, $294.8M). Held out, leave-one-out on the 128 traded tokens, radar-6 predicts market caps with a median error of 3.96× against 5.53× for the peer multiple alone, winning 67.2% of comparisons; on the rankable-like subset (n=87) 3.96× vs 4.99×, win 67.8%. The unbounded curve is better held out still (3.23×) — the 2× bound is a stated prior, not a fit. Momentum, maturity and chain breadth were disclosed sensitivities through radar-5 and are dropped in radar-6: the full formula scored 4.20× held out against 3.96× for the peer × size multiple alone, so the simpler model is adopted and the three multipliers ship as 1.00. Token odds are a fitted logistic on log TVL, 7-day growth and log chains, offset by the shrunk category rate (10-fold Brier 0.149 vs 0.152 for the v3 rate, AUC 0.650 vs 0.613; 4-fold 0.150 vs 0.155, AUC 0.650 vs 0.600); age is excluded because it rises mechanically with age — an age term was tested again in radar-6 and rejected (it wins 10-fold in aggregate but loses on old protocols in the forward time split, and the board is old no-token survivors). Expected value is implied value times token odds. Each row carries a farm verdict at a sized deposit — twice its break-even deposit, capped at ten times the plan deposit (70 FARM / 61 THIN / 63 SKIP); expected net at the sized deposit is positive on every FARM row by construction. Each row carries a rank range (P10–P90 across 200 bootstrap refits of the fitted model) — a stability statement, not a calibrated interval: on traded comparables the true rank falls inside it only ~21–23% of the time. No per-row value band is shown: every candidate holding ~80% of held-out values was 83–258× wide, and no honest construction reaches 75% coverage at 10× width or less. The dashboard recomputes every row's implied value and token odds in the page from data.js alone and shows a self-test strip reporting PASS/FAIL per check. Wrapped, staked, bridged and stablecoin products are left out of the board and listed with their reasons; the two stablecoins on the watchlist stay on the board, flagged, because the watchlist is the floor. No walk-forward claim: the snapshot is a single date (2026-11-14), and no FDV field exists in it.

## Run it

```sh
mkdir -p out && MAKEFUN_OUTPUT_DIR=out node main.ts --input snapshot.json
```

`main.ts` reads the sealed snapshot (the grader mounts it at `/input/snapshot.json`), writes the ranked board to `out/board.json`, the dashboard's data to `out/data.js`, and copies `dashboard/` and `screenshots/` to `out/`. It writes `out/dossier.json` last. Node 22, standard library only, no network.
